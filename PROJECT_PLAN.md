## Site architecture

Static site, no build step (GitHub Pages compatible — no bundler, no server-side code, everything CDN or local file references).

```
index.html                          — home page
case-studies/
  table-modernization.html
  navigation-modernization.html
prototypes/
  action-slot-grid/                 — verbatim copy of Assets/Action_Slot_Grid_Prototype
styles/
  tokens.css                        — CSS custom properties: grid, type scale, color
  base.css                          — reset, base type, .container / .grid-12 utilities
  components.css                    — nav, modal, shared .btn-action style
  home.css
  case-study.css
scripts/
  nav.js                            — scroll-driven nav show/transform/hide + active/hover underline
  modal.js                          — iteration-examples modal: open/close, focus trap, Escape, scrim click
  media.js                          — scroll-triggered play-once + Replay; compare/pause toggle
Assets/                             — unchanged, consumed by the pages above
```

`scripts/overlay.js` still exists on disk (archived, not deleted — see `ARCHIVED_FEATURES.md`) but isn't linked from any page.

`LottieAnimations/` and the `lottie-web` CDN `<script>` tag are removed in Phase 1 once both home-page comparisons point at the new mp4s.

## Component specs

### Navigation (`scripts/nav.js`, `.site-nav` in `components.css`)
- Wordmark left: full name "KAYLA ANN JAMES TURNER", Barlow 400 14px, `--color-nav-wordmark` (`#484848` — deliberately darker than body gray to keep visual presence at this smaller size); shortens to "KAYLA AJ TURNER" below 600px.
- Links right: Home / P1 – Table / P2 – Navigation, **Merriweather** 400 15px (`--text-nav`), `--color-body` (`#5c5c5c`) — not Barlow/ink, easy mistake since every other UI label on the site is Barlow. Shorten to "Table" / "Nav" below 600px (same pattern/breakpoint as the wordmark) since the full labels don't fit next to the full wordmark on narrow phones.
- Sizes step down gradually: desktop → ≤900px → ≤600px, three tiers, not a single mobile cutoff.
- Underline: hover uses `--color-underline` (`#d4d4d4`, light); the active link uses a separate, darker `--color-underline-active` (`#8a8a8a`) so the current page reads as more prominent than a hover state.
- Bar height: `--nav-height` (56px).
- **Home page**: nav is not present over the hero. An `IntersectionObserver` on the name (`.site-name` specifically, not the whole hero block) toggles a `.site-nav--visible` class once the name scrolls out of view — the trigger point is the name itself, not the subtitle/tagline/divider below it. Nav then stays pinned (`position: fixed`) for the rest of the page.
- **Case study pages**: nav is present from the top. A scroll-direction listener (rAF-throttled) hides it on scroll-down and reveals it on scroll-up, with a small threshold near the top of the page so it doesn't flicker.
- **Returning to home from a case study**: `nav.js` bakes a `#nav-visible` hash onto the Home/wordmark links' actual `href` as soon as a case-study page loads (not intercepted at click time, not sessionStorage — see the file's own top comment for why). On home page load, if that hash is present, it triggers an instant (non-smooth) scroll to just below the hero and immediately shows the nav, so the visitor doesn't land back at the very top hero view they've already seen.
  **If this ever looks broken while you're testing a change to it, verify against a test file whose name actually ends in `index.html` before concluding the restore logic is at fault.** `nav.js`'s selector (`a[href$="index.html"]`) won't match a differently-named test copy (e.g. `test_dest.html`, `_indextest.html`) — this cost real debugging time once already (see DECISIONS.md's "Return-to-home nav restore" entry for the full story) before the actual cause turned out to be the test file's name, not the site's code.

Stacks to a single left-aligned column below 900px (`.case-header-row { flex-direction: column }`, `.case-role` reset to `text-align: left; max-width: none`).

The role-line treatment was deliberately **not** brought over to the home page cards — `.project-description` + the "View case study" button already occupy that "summary" position next to the title, so there's no equivalent line to move.

### Item content (Issues discovered / Key design decisions)
- **Text always comes before its media**, not after — every `.case-asset` reads: subheading, then any body text/list, then the asset block(s). Applies across the whole page (Core driver, AI section, etc. already did this; Issues discovered/Key design decisions were reordered to match).
- **`.item-heading`** is the suggested-and-adopted subheader style for each numbered item's title line: Merriweather **Bold**, `--text-item-heading` (16px), `--color-ink`. Deliberately a different family (serif vs. the Barlow used everywhere else) so numbered items read as distinct titles without needing bullet markers to do that job.
- **Both sections are numbered** — "1. Visually noisy", "2. Interaction inconsistencies", etc., restarting at 1 per section. The number is plain text prefixed onto the `.item-heading` string, not a separate styled element.
- **Bullets removed from the two-bullet Key design decisions items**; each former bullet is now its own `.case-prose` paragraph, paired with (immediately followed by) the specific image it refers to. For items with two images (Consolidated filtering, Gave column editing space), this means the sequence interleaves: heading → prose → image → prose → image. For items with one image (Improved visual design, Quick actions), both prose lines stack before the single image.
- **Bulleted lists (`.item-list`) are kept** for short-item enumerations that aren't tied to a specific image — "Visually noisy" lists its specific issues this way (parenthetical text from the source doc converted to list items, parens removed). This is a deliberate distinction from the point above: short tag-like items stay a list; full-sentence bullets that each map to one image become paired prose+image instead.
- **`.item-list--horizontal`** (added to "Visually noisy" only, per Kayla's request) runs the list items left-to-right via `flex-wrap: wrap` instead of stacking one per line, so short tag-like items ("Color", "Alignment", "Spacing"...) use the row's full width when there's room and wrap naturally at narrow widths.
- **"Filtering confusion" reverted to its original single line** — "Filtering confusion (global vs local, separated, different visuals)," verbatim from `Assets/Portfolio text.md`, parentheses included. It was briefly split into an `.item-list` in the same pass that added "Visually noisy"'s list, then reverted per Kayla's follow-up request; it's the one item in this section with no bulleted breakdown.
- **"Interaction inconsistencies" has an added example line** not in `Assets/Portfolio text.md` — "For example, dashed underlines usage not all having hover interactions" — added at Kayla's direction, in `.case-prose` (body text), not the source doc. If re-syncing content from that file later, don't drop this line.
- Spacing between everything inside a `.case-asset` is generic (`.case-asset > * { margin-bottom: 16px }`, last child excluded), not hand-tuned per combination — this is what makes the interleaved paired-image structure and the simple single-image structure both space out consistently without separate rules.
- **Two exceptions to that generic rule**:
  - A caption that follows a *different* media block (the interleaved items — "Consolidated filtering," "Gave column editing space") gets extra space above it (`.case-asset > .case-asset-block + .case-prose { margin-top: 40px }`) so it visually binds to the image below it, not the one above. Without this, a second caption sat exactly halfway between its own image and the previous one (both 16px gaps), reading as ambiguous about which it described.
  - Two (or more) directly-consecutive body-text lines with no media between them (e.g. "Merged scope and context..."'s pair of bullets-turned-paragraphs, or the Table page's "Improved visual design..."/"Quick actions...") get a much tighter `margin-bottom: 4px` instead of the generic 16px (`.case-asset > .case-prose:has(+ .case-prose)`) — they read as a related pair, closer to how list items relate to each other, not as two separate unrelated blocks.
- Spacing *between* separate `.case-asset` items (i.e. between one numbered issue/decision and the next) is `72px` — increased from an initial `40px` once the numbered/heading structure was in place, since 40px read as too tight once each item had its own titled heading rather than just flowing prose.
- "View iteration examples" (Consolidated filtering only) sits in a `.item-heading-row` alongside its item's heading — top of the item, not trailing after the media. This restores the "aligned to the top of the text, same row" placement from the original overlay-based design after it briefly moved to a bottom `.case-section-actions` slot during the overlay removal; the bottom slot is still used for standalone single actions with no heading beside them (e.g. Microsoft Advertising, right-aligned by default via `.case-section-actions`, or left-aligned via `.case-section-actions--start` when the action reads as its own line rather than a trailing CTA).
- **`.item-heading-row` is `position: relative`, not a flex row** — the button (`.item-heading-row .btn-action`) is `position: absolute; top: 0; right: 0`, taken out of flow entirely. A flex row's height is the taller of its children, and `.btn-action` (~37px) is taller than `.item-heading`'s own 24px line, so as a flex sibling it was inflating the row's height and breaking the heading-to-text spacing match with every other section — see DECISIONS.md. `.item-heading` gets `padding-right: 260px` so its text always wraps clear of the button rather than risking overlap at any viewport width; mobile (≤600px) resets the button to `position: static; width: 100%` to stack it back below the heading.
- Description text max-width: 8 of 12 grid columns (`.text-measure`) at wide desktop; goes to full width below an 800px viewport. Applied to `.item-heading`, `.case-prose`, and `.item-list` throughout these two sections.

### Iteration modal (`scripts/modal.js`, `.iteration-modal`/`.iteration-modal-scrim` in `case-study.css`)
- One per case study page, opened from the single "View iteration examples" trigger mid-page (`[data-open-modal]`).
- Desktop: slides in from the right, `width: min(1040px, calc(100% - 160px))`, leaving both page edges + a scrim visible. Mobile (≤900px): full-bleed, no scrim.
- Close via `Assets/Dismiss.svg` button (top right), clicking the scrim, or Escape. Basic focus trap; focus returns to the trigger button on close.
- Content is grouped by the source doc's `#####` sub-headings (`.iteration-modal-group`), not flattened — some groups have one image+paragraph per item (Table's "Bulk/supportive information filters"), others share one paragraph across two images (Smart/AI Filters, filter-carry). Follow `Assets/Portfolio text.md`'s exact grouping per case study rather than assuming every modal groups the same way.
- **Groups are separated by whitespace only, no divider line** — `.iteration-modal-group`'s `border-top` was removed after Kayla flagged the repeated hairlines as visual noise once the surrounding spacing/sizing passes landed; `padding-top/bottom: 32px` on each group still does the separating.
- **Group titles (`.iteration-modal-group-heading`) use the same `.item-heading` subheader style** as Issues discovered / Key design decisions (Merriweather Bold, `--text-item-heading`, `--color-ink`, 8px margin-bottom) instead of their own separate Barlow/20px treatment — for visual consistency across the page. Kept as its own CSS class (not the literal `.item-heading` class) since it's a group label, not a numbered item title, and isn't numbered.
- **Text before media, same as everywhere else on the page**: each `.iteration-modal-item` reads paragraph → `.iteration-modal-media-row`, not the reverse. The paragraph carries the spacing to its own media (`.iteration-modal-item p { margin-bottom: 16px }`) rather than the media-row carrying it, so the same rule works regardless of which element is now last.
- **Every image is one per row, always — nothing in this modal sits side by side**, confirmed against `Table Page Modernization - Iteration Modal.png`. Groups with two images stack them vertically under the shared paragraph; there's no `.is-paired`/2-column variant here (unlike some contexts on the main page).
- **Surface applies only to isolated component mockups, not full product screenshots** — same rule as the main page's assets. In the Table modal, that's the two "Bulk/supportive information filters" images (`.iteration-modal-media.surface`, matching the reference's gray card behind that floating Filters-panel mockup); the Smart/AI Filters and filter-carry screenshots are full-bleed with no wrapper.
- **Those same two images sit inside a shorter box** via `aspect-ratio` set inline on each `<img>` (`1132/855` for Modal 1, `1132/681` for Modal 2) — both SVGs export with extra empty canvas below their visible content (Figma's shadow/bleed allowance), which read as an unbalanced surface card (more gray below the panel than above). **Use `object-fit: contain`, not `cover`**, to fit the image into that shorter box — `cover` was tried first and clipped into the still-visible tail of the drop shadow (a shadow fades gradually with no hard edge, so "looks faint" isn't the same as "fully ended"). `contain` shrinks the whole image to fit with nothing cropped, at the cost of a small even letterboxed margin on the left/right instead of edge-to-edge fill — see DECISIONS.md for the full before/after. If either asset is ever re-exported, its aspect-ratio needs re-measuring, and any future case of "trim a card to be shorter than its image" on this site should default to `contain`, not `cover`, for exactly this reason.
- **`.iteration-modal-media.surface` (only ever these same two cards) also drops its bottom padding to 0**, on top of the `contain` fix — the shared `.iteration-modal-media { padding: 24px }` was still adding an even strip of gray below the now-shrunk image, on top of what the image's own internal shadow-bleed margin already left. Scoped to `.surface` specifically so every other `.iteration-modal-media` card (and every other `.surface` card on the main page) keeps its normal uniform padding.
- **This exact technique was generalized into a reusable class, `.surface--shadow-trim`** (`case-study.css`), once the same shadow-bleed problem showed up a second time on the Navigation page (`Browse Tools Dialog.svg`, see Key design decisions below) — `padding-bottom: 0` + `img { width:100%; height:auto; object-fit:contain }`, paired with a per-image inline `aspect-ratio` measured the same way. The Table modal's two images still use their own inline rules rather than this shared class (not retrofitted, since it wasn't asked for) — if either is touched again, consider switching them to `.surface--shadow-trim` too instead of maintaining two copies of the same fix.

### Media behavior (`scripts/media.js`)
- Case study mp4s: `IntersectionObserver`-triggered play-once (threshold 0.4) when scrolled into view; a `.case-media-replay` button (`hidden` by default) is revealed on the video's `ended` event.
- Case study animated SVGs (only one currently: `Filters-Scattered-Animation.svg`, the sole asset with embedded CSS `@keyframes` — checked every Table/Nav SVG for `<animate`/`@keyframes`/`animation:` before deciding this): plain `<img>`, same as every static SVG on the page — **no JS involved at all**. It used to be loaded via `<object type="image/svg+xml">` specifically so `media.js` could reach into `obj.contentDocument` and gate playback to scroll-into-view, but that was dropped after confirming (with a real headless test) that `contentDocument` is always `null` for an `<object>`-embedded document under `file://` — the exact context this site gets reviewed in. See DECISIONS.md for the full root-cause writeup.
- Home page + case study comparison mp4s (`.media-compare`): existing Compare/Pause toggle behavior kept, restyled to the shared `.btn-action` look.
- Videos use `preload="metadata"`, `muted playsinline` for autoplay-on-scroll to work cross-browser. **Every video also gets `paintFirstFrame()` called on it** (shared helper at the top of `media.js`): seeks to `currentTime = 0.01` once metadata loads, forcing that one frame to be fetched/decoded and painted immediately — without this, `preload="metadata"` shows nothing at all until playback actually starts, which reads as "the video never loaded." Applies to `.media-compare` videos too, not just `.case-media` ones.
- **`.case-media video` has no `loop` attribute** (only `.media-compare` videos loop — they're a continuous before/after comparison, a different feature). A case-study asset video must actually reach its end to fire the `ended` event that reveals the Replay button; `loop` prevents `ended` from ever firing.
- **`.case-media video` renders at its native recorded size, not stretched to the column width** (`width: auto; max-width: 100%`, not `width: 100%`) — upscaling past native resolution read as "way too large" and blurry. Full-bleed `<img>` SVGs keep `width: 100%` since vector art scales losslessly and the reference shows full-bleed screenshots — **except** inside a `.surface` card (`.case-media.surface img`), which gets the same native-size-capped treatment as video for the same reason: an isolated UI fragment stretched edge-to-edge inside a card reads as oversized (see Table Issues 3 below).
- The one animated SVG (`Filters-Scattered-Animation.svg`) plays **exactly once, permanently — fixed in the SVG file itself**, not with runtime JS. Its four animated elements originally had `animation: <name> 0.948088s linear infinite`; all 8 `infinite` occurrences were changed to `1`, then later all 8 also got `forwards` appended (`linear 1 forwards`) so each element holds its finished state (full opacity/scale) instead of snapping back to its blank pre-animation look once the one-shot animation ends. It plays immediately on page load now (see above — no more scroll-gating), not on scroll-into-view, and has no Replay control — Kayla confirmed a one-shot animation doesn't need one. **If another animated SVG on this site is reported as looping or resetting, fix the `animation` shorthand's iteration-count/fill-mode in the source file first**, not a runtime override.

## Asset-to-section mapping

Fully resolved — `Assets/Portfolio text.md` gives the exact section copy with inline `[Table - Main N - Name]` / `[Navigation - Main N - Name]` markers showing precisely which asset sits where, plus where each button/embed/modal-trigger goes. Build Phase 3/4 sections directly off that file, top to bottom, one `.md` "paragraph block" (separated by `---`-free blank lines) per page section. No more inference needed.

**Layout rule, corrected after Phase 3 review:** every asset is full-width, one per row — never side-by-side, never a multi-up grid. Where two `[Main N]` markers appear together before one shared caption, render them as two stacked full-width rows (see "Item content" below for how the shared caption is now split between them, one paragraph per image).

**One deliberate, named exception to that rule:** Navigation's "Replaced 'Tools' junk drawer..." (Key design decisions #1) uses `.case-decision-columns`/`.case-decision-col` — two columns side by side in one row, where each column is its own self-contained text-above-image group (not text-left/image-right, and not all-text/all-images split into two columns — both were tried first and corrected; see DECISIONS.md for the full three-attempt history). Heading sits full-width above both columns. Both images keep `.surface`. ## Performance

**Done, no build step needed:**
- **Native lazy-loading** (`loading="lazy"`) added to every `<img>` and `<iframe>` across all three pages — zero risk, since the browser only defers requests for elements not yet near the viewport; verified via a full-page headless screenshot that a far-below-the-fold image still renders correctly. - Confirmed Google Fonts loading already follows best practice on every page: `rel="preconnect"` to both `fonts.googleapis.com`/`fonts.gstatic.com`, plus `&display=swap` on the stylesheet link (avoids invisible-text-during-font-load). No changes needed.

**Flagged, not yet applied — needs Kayla's call:**
- **The same ~265KB avatar photo ("Mona Kane," the Microsoft Advertising mock user) is independently embedded as base64 inside 9 separate SVG files** — `Table - Main 4 - Filters-Scattered-Animation.svg`, `Table - Modal 3/4 - Smart AI Filters 1/2.svg`, and `Navigation - Modal 1 through 6.svg` (Dropdowns Header, Merge into secondary 1/2, Collapse Filters 1/2/3). Confirmed by hashing each embedded image — all 9 are byte-for-byte identical. Each file pays the full ~353KB (base64-inflated) cost independently; there's no way for the browser to dedupe or cache across them since they're technically 9 different file URLs each containing their own inline copy. That's roughly **3.2MB of the ~8.2MB total SVG weight being one repeated image** — by far the single biggest lever available on this site's performance, dwarfing anything otherwise tunable in CSS/JS.
  - **The fix** (extract the avatar to one shared file, e.g. `Assets/avatar.png`, and change each SVG's embedded `<image>` to reference it externally via `href="../avatar.png"` instead of an inline data URI) **was not applied** — it requires editing 9 separate, complex Figma-exported SVGs, each individually, with real risk of subtly breaking one if the edit isn't precise. These are Kayla's design-source files, not code this project owns outright, so this needs her go-ahead (and ideally her doing it via Figma re-export with "linked" rather than "embedded" images, if that's supported in her export flow, rather than me hand-editing the SVG XML).
